# Procedural jump for FrogBoss — UE 5.7

Положение лап рассчитывает CR_FrogBoss_ProceduralJump во время игры. BP_FrogBoss_ProceduralJump содержит меш и ControlRigComponent с привязкой всех 34 костей. Python нужен только для пересборки ассетов и запуска проверок в редакторе.

## Установка

Готовые ассеты находятся в Content/RiseAboveIt/Mobs/FrogBoss в корне репозитория. При переносе в другой проект сохраняйте пути Content. Нужен включённый плагин Control Rig. Используются общие M_Palette и T_Palette текущего main; их замена этим комплектом не требуется.

Карта: /Game/RiseAboveIt/Mobs/FrogBoss/Maps/L_FrogJump_RuntimeTest. На ней один BP_FrogBoss_ProceduralJump. По умолчанию JumpAlpha=0, поэтому автоматической атаки после Play нет.

## Подключение к AI или Blueprint

Из компонента JumpRig получите Get Control Rig. Его публичные переменные можно менять через Set Variable From String; в AnimBP используйте узел Control Rig и подайте те же параметры на входы. Не подключайте одновременно компонент и AnimBP, которые записывают одни и те же кости.

В начале прыжка зафиксируйте точку приземления. Переведите её из мировых координат в пространство компонента меша и вычтите JumpStart. Это JumpTarget. Не обновляйте цель за игроком во время полёта: ему нужно окно для уклонения.

| Переменная | Значение |
| --- | --- |
| JumpTarget | Смещение от старта к цели в пространстве компонента, сантиметры. Для прыжка вверх (0,0,0). Пример строки: (X=0,Y=1000,Z=0). |
| JumpStart | Положение root в том же пространстве на старте. Обычно (0,0,0). |
| JumpAlpha | Фаза полёта 0..1. Продвигайте её игровым Timeline или таймером после замаха. |
| JumpHeight | Добавка к линейной траектории на середине полёта. По умолчанию 806.8412 см. |
| JumpWeight | Вес процедуры 0..1. При 0 исходная поза сохраняется. |
| DriveRootWeight | 1: риг двигает root по параболе. 0: root должен перемещать внешний код или анимация. |
| GroundHeight | Высота горизонтальной поверхности в пространстве компонента. По умолчанию 0. |

Формула root: JumpStart + JumpTarget*t + Up*4*JumpHeight*t*(1-t). Вектор вытягивания лап противоположен начальному направлению прыжка. При вертикальном прыжке лапы уходят вниз. Переход выполняется смещением IK-цели; длина сегментов сохраняется.

Режим DriveRootWeight=1 перемещает только кости меша. Капсула Actor от этого не перемещается. Для игрового Character задавайте траекторию Character Movement и используйте DriveRootWeight=0, согласовав JumpStart, цель и GroundHeight с движущимся пространством компонента. Этот режим проверен на сохранение внешнего root; полноценная интеграция с Character Movement ещё не выполнена.

Высота около 8 м выбрана с учётом длинных задних лап текущей модели. При уменьшении высоты лапы будут сгибаться из-за ограничения поверхности. Ограничение пола относится к плоской поверхности и целям кончиков; трассировок рельефа, препятствий и компенсации столкновений тела пока нет.

## Замах и приземление

Замах должен предшествовать росту JumpAlpha: ориентир текущего клипа 0.9 с. Полёт — примерно 1.17 с (кадры 27..62 при 30 fps), затем восстановление. Сам риг не отсчитывает время, не выбирает цель и не вызывает урон. Приземление и урон запускаются один раз игровой логикой при завершении полёта. Старый клип JumpSlam с запечённым root одновременно с этим перемещением не воспроизводить.

В пакете сохранены Idle, Death и Tongue. При подключении через AnimBP процедура накладывается на входную позу. Демонстрационный Actor с компонентом выводит отдельную процедурную позу и пока не содержит боевой state machine.

## Проверено

UE 5.7, Play In Editor: один и тот же Actor и меш, четыре цели, семь фаз полёта, всего 28 поз. Все 34 кости меша совпали с результатом рига. Длина костей сохранилась; направление задних лап на вершине совпало с направлением, противоположным толчку. Дополнительно проверены веса 0, 0.5 и 1 и отключение перемещения root.

Отчёты: ../Reports/runtime_mesh_test.json и runtime_weight_test.json. Это проверка поз в PIE, не тест боя и не проверка packaged build. Исходники создания ассетов находятся рядом. verify_pie_mesh.py запускается через редакторский Python после Simulate на тестовой карте; путь OUT в скрипте нужно указать для своей машины.
